# TradeLink Group Engagement

> **This is a simulation, not client work.** TradeLink Group is a fictional company.
> This repository documents a self-directed Salesforce project built to develop
> and evidence implementation skills. No real customer data appears anywhere in it.

**Certification track:** Advanced Administrator, Sales Cloud Consultant, Service Cloud Consultant
**Salesforce org:** Developer Edition (CLI alias `tradelink`)
**Scope:** 8 sprints | trust tickets, security model reset, equipment registry, automation suite, acquisition data migration, contact centre SLAs, board dashboard, packaged go-live

## The brief

Eight sprints inside a national home-services franchise network with 450 staff, three brands and six years of organic growth in the org.

## What's in here

| Folder | Contents |
|---|---|
| `force-app/` | Salesforce metadata retrieved from the org — the configuration itself |
| `seed/` | Apex scripts that build the starting data, including its deliberate defects |
| `deliverables/` | The written work: design docs, SOPs, analyses, runbooks |
| `evidence/` | Before/after screenshots and test results per phase |

`deliverables/` is the substance. The configuration proves the clicks happened;
the documents prove the thinking did.

## Progress

Build log lives in `deliverables/build-log.md` — every change with its date,
reason, and the requirement it traces to.

## For recruiters and agencies

**What this repository evidences:** the scope and design discipline for a brownfield,
multi-brand org — trust tickets before automation, a security reset before the automation
that depends on it, and deletions recorded as decisions rather than done quietly.

**State as at 06/09/2026:** Scoped; org provisioned. No sprint has been built yet, and
this README will say so until one has.

1. [`deliverables/build-log.md`](deliverables/build-log.md) — the record so far
